重點摘要

我怎麼做

用白話中文講需求、貼參考網址、貼截圖回報問題。不需要自己寫程式，也不需要一次講完整規格——邊做邊講、逐輪修正。

做出了什麼

8 頁示意站：開場倒數計時、百年大事記（每 10 年摺疊）、歷任院長、真實院內新聞、院區捲動敘事、系列活動、禮品等。

誰負責什麼

我負責方向、事實與邊界（例如「現任院長是陳建仁」「不要攻擊別人的網站」）；AI 負責查資料、實作、測試與自我修錯。

協作方式

每一輪都是同一個小循環

整個專案沒有「一次交付」。每輪我提一個需求或問題，AI 動手做並自己驗證，我看成果再回饋，接著下一輪。

我：講需求 / 貼網址 / 貼截圖→ AI：查資料、寫程式→ AI：開瀏覽器自己驗證→ 我：看成果、糾正、補事實↻

一步一步

製作歷程

起點：資料夾裡已有前期資料（《籌備時程與採購規劃》需求文件、內容分析報告、影片腳本、捲動敘事骨架）。以下從本次工作階段的第一句話開始。

01

先分析參考網站 分析

我說「幫我分析（籌備文件）裡面提到的網站　大概就好 不用全部都爬取　了解其中使用的技術——網站架設是什麼框架、裡面的呈現用了什麼套件……是否有用 CDN、放在雲端還是自己的主機。請不要以攻擊的方式看別人的網站喔」
AI 做了什麼
  • 從需求 .docx 的超連結找出 15 條連結（12 個網域）（政大、台大、故宮、CERN、LSE、Stanford、中研院院慶站…）
  • 以一般訪客的方式各請求一次首頁（命令列請求帶瀏覽器樣式的 User-Agent，加上內建瀏覽器開頁），讀公開的 HTML 與 HTTP 回應標頭判斷技術，不掃描、不探測
  • 中研院院慶站：命令列請求得到 401，再用內建瀏覽器開一次，看到「IP 已被封鎖」頁面後就停手，沒有嘗試繞過，並如實回報「只能推論它是自架 + WAF」
  • 整理成比較表與結論

04

AI 自己測出第一個 bug 踩坑

AI 做了什麼（我沒有提醒）
  • 驗證時發現頁面「自己一直往下捲」（約每秒 180px）
  • 追出原因：body 的 overflow-x:hidden 讓 body 變成捲動容器，和平滑捲動套件 Lenis 互相拉扯
  • 改成 overflow-x:clip，並停用瀏覽器自動還原捲動位置；重測確認位置不再漂移
05

一輪輪的調整：換影片、貼截圖回報、收斂內容 把關 1–3（②③④）

我說（前後幾輪，原話） ① （AI 還在做事時直接插話）「一開始影片換成這個（YouTube 連結）　然後從 24 秒開始喔」
② （貼截圖：影片區顯示「錯誤 153」）「為什麼我直接開 INDEX 就會錯誤 153」
③ （貼截圖：時間軸年份與圓點擠在一起）「這個 2027 Q1 與圈圈靠在一起了」
④ 「院長的照片　幫我用一個框框就好　因為那個不是現在院長，百年禮品也用框框就好」
AI 做了什麼
  • ① 換影片：改用 YouTube IFrame API 做全螢幕背景（靜音、自動播放、循環時跳回第 24 秒）；第一次沒出現，查出是自己加的背景色蓋住了「負 z-index 的影片層」，修好；「形象影片」區塊也換成同一支
  • ② 錯誤 153：原因是直接雙擊開檔（file://）沒有網域，YouTube 拒絕內嵌；加了保護，偵測到 file:// 時改顯示靜態主視覺與「在 YouTube 觀看」連結
  • ③ 時間軸擠在一起：重新配置欄位（年份欄 ┊ 間距 ┊ 內容欄），圓點置中於直線、兩側各留固定間距；兩頁都驗證
  • ④ 框框：新增可重用的「佔位框」，替換院長照片與所有禮品圖；輪播方框太高順手改成橫式；只改我指定的「一個」院長照片，並主動說明「歷任院長」小頭像沒動、要的話再一起換

  • 提醒：對話記錄不會跟著資料夾走，所以才要把脈絡寫進檔案

溝通心法

這次有效的 7 種說話方式

① 先講界線

「大概就好」「不要以攻擊的方式」。界線在前，AI 行為就會保守。

② 給參考、給素材

「仿照政大」＋貼自己的站。比抽象形容詞（「大氣一點」）更準。

③ 硬性條件單獨點出

「一開始要有倒數」——放在句尾強調，AI 會當成必做項。

④ 截圖 + 一句話回報 bug

不必懂技術；畫面 + 「這裡怪怪的」就足夠定位。

⑤ 一次交代多件事

一則訊息講好幾件事，AI 逐項完成並回報，省去來回。

⑥ 事實由人給來源

有些資料過舊（例如院史網），所以不知道現任已是陳院長。我貼上新的歷任院長連結，讓 AI 去查證，而不是憑印象。

⑦ 要求寫進檔案

「做成一包、換電腦能繼續做」——把脈絡存成 CLAUDE.md 等檔案，跨電腦也接得上。

分工

人負責什麼、AI 負責什麼

我（人）

  • 決定方向與範圍（做什麼、不做什麼）
  • 提供事實與素材來源（現任院長、影像展、影片）
  • 設定安全與倫理界線（例如不攻擊別人的網站）
  • 驗收成果並糾正（框框、時間軸擠在一起）
  • 對外負責：內容正確性、圖片授權

AI

  • 查資料與分析（8 個網站的技術判讀）
  • 把口語需求拆成頁面、設計系統與程式
  • 撰寫 HTML / CSS / JS 並在瀏覽器實測
  • 自己找 bug、修 bug、說明原因
  • 整理文件與交接（分析報告、CLAUDE.md、zip）
